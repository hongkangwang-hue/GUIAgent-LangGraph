## 四、两件挂起的事，详细状态

### 4.1 LangGraph 框架：代码好了，没验证

**背景**：大纲 W3 任务 2 要求"基于 LangChain/LlamaIndex 搭建 Agent 框架"，
而 v1.0 的执行循环是自写的，LangChain 只用在调模型那一层。这个偏离在 W3
交付包 README 里声明过，现在用 LangGraph 补上。

**做到哪了**：

| 阶段 | 内容 | 状态 |
|---|---|---|
| 1 | 执行循环改由 `StateGraph` 编排，与手写版并存 | ✅ 代码完成，单测全绿 |
| — | **客机端到端 A/B 对照** | ⬜ **一次没跑**（存档里没有任何带 `engine` 字段的记录） |
| 2 | 会话编排改成图 | ⬜ |
| 3 | 提示词改用 `ChatPromptTemplate` | ⬜ |
| 4 | 急停与人工干预用 `interrupt` 建模 | ⬜ |

**为什么不能跳过验证**：两个引擎各有一份单步逻辑（这是"并存到验收为止"的
代价）。9 月 22 日合并主仓库时，git 报告无冲突，**但等价性测试红了 5 条**
——安全整改改了 legacy 的帧差逻辑，图版没跟上。这类偏离只有实测能兜底。

**要做什么**：客机上同快照、同模板，`--engine legacy` 与 `--engine langgraph`
各跑一轮，比对成功率与轨迹。约 1 小时。

### 4.2 模型微调：离线好，端到端无效

**离线指标（375 条验证集，微调前 → 后）**：

| 指标 | 前 | 后 |
|---|---:|---:|
| 格式合规率 | 24.0% | **100.0%** |
| 动作类型准确率 | 15.5% | 59.7% |
| 坐标误差中位数 | 144.5 px | **49.7 px** |
| `done` 误报率 | 7.8% | **36.5%（变差）** |

**端到端**：1024×768 干净基线 **0/25**，而在线 8B 是 24/25。

**已定位的三个原因**：

1. **分辨率不同构**：训练集 100% 是 1024×768，客机曾长期跑 1920×1080。
   单变量实验：坐标误差 49 → 255 px。客机已改回 1024×768。
2. **`done` 过拟合**：训练集里 `done` 占 41.6%，修好的上界是动作类型
   59.7% → 81.1%。**未重训。**
3. **域不匹配**：训练集 0 条客机截图，"开始按钮"标在 Win10 左下角，
   客机是 Win11 底部居中。

**已否掉的方案**：租 GPU 上 7B/8B。同一批验证集上 8B 只比微调 3B 高 2.8pp，
端到端却高 5.6 倍——差距在任务拆解粒度（3.6 vs 2.1 子任务）上，换更大的
模型买不到。

**正在推进的方案（蒸馏试点）**：用在线 8B 在客机上做成功的轨迹当训练数据。
数据管线代码已完成（采集任务集、导出通道、轨迹转样本，63 条测试），
**卡在三件事上**：

- ⬜ Qwen3-VL 许可证：输出能否用于训练，未查
- ⬜ 客机是否有画图程序（采集任务用到 `mspaint.exe`），未确认
- ⬜ 干净快照（无 `.env`、不登录真实账号）是否就绪
