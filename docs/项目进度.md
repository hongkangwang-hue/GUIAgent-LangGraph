### 4.2 模型微调：离线好，端到端无效

**离线指标（375 条验证集，微调前 → 后）**：

| 指标 | 前 | 后 |
|---|---:|---:|
| 格式合规率 | 24.0% | **100.0%** |
| 动作类型准确率 | 15.5% | 59.7% |
| 坐标误差中位数 | 144.5 px | **49.7 px** |
| `done` 误报率 | 7.8% | **36.5%（变差）** |

**端到端**：1024×768 干净基线 **0/25**，而在线 8B 是 24/25。

**已定位的三个原因**：

1. **分辨率不同构**：训练集 100% 是 1024×768，客机曾长期跑 1920×1080。
   单变量实验：坐标误差 49 → 255 px。客机已改回 1024×768。
2. **`done` 过拟合**：训练集里 `done` 占 41.6%，修好的上界是动作类型
   59.7% → 81.1%。**未重训。**
3. **域不匹配**：训练集 0 条客机截图，"开始按钮"标在 Win10 左下角，
   客机是 Win11 底部居中。

**已否掉的方案**：租 GPU 上 7B/8B。同一批验证集上 8B 只比微调 3B 高 2.8pp，
端到端却高 5.6 倍——差距在任务拆解粒度（3.6 vs 2.1 子任务）上，换更大的
模型买不到。

**正在推进的方案（蒸馏试点）**：用在线 8B 在客机上做成功的轨迹当训练数据。
数据管线代码已完成（采集任务集、导出通道、轨迹转样本，63 条测试），
**卡在三件事上**：

- ⬜ Qwen3-VL 许可证：输出能否用于训练，未查
- ⬜ 客机是否有画图程序（采集任务用到 `mspaint.exe`），未确认
- ⬜ 干净快照（无 `.env`、不登录真实账号）是否就绪

`loop_status=plan_failed`、起点检查通过、点击上限 4、无动作步骤；
进一步脱敏分类确认是 `backend_call`，即规划时的百炼接口调用失败；
旧轨迹的错误类别进一步确认是 `quota`。这表示接口返回了额度或配额相关
错误，脱敏摘要不能区分具体子类型。Planner 已补上仅对可重试接口错误进行
一次补试，并记录调用次数和错误类别；`quota` 被判为不可重试，因此该修复
不能解释或挽救这次旧失败。后来的一次成功说明接口并非持续不可用；新版
重试逻辑仍待客机实测。
这些是两次单轮探索性试跑，不构成稳定成功率。主机另修存档反复新建截图
器的问题：复用开跑时的首帧记录分辨率、DPI、截图引擎，并在结束时关闭
截图器；该改动尚未在客机实测。
