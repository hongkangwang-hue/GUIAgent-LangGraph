## 0. 先说清楚 M4 的成功标准是什么

翻遍 11 条验收标准，**没有一条要求端到端成功率达到某个数**。
与 M1、M3 一样，本项目通篇不设硬性性能门槛。

它要求的是三件事：

```
1. 做出东西    Reflector / 恢复模块 / 监控面板 / 系统 v2.0
2. 量出数字    触发率、恢复率、延迟四段、OCR 次数、召回率
3. 说清来源    每处改动能对应到 D1 错误分类里的具体失败案例
```

**第 3 条是这个里程碑的灵魂**——标准 8 原文要求「每一处参数改动都能对应到
D1 错误分类中的具体失败案例」。所以路径必须是**先跑出失败 → 分类 → 再改**，
不能先猜再改。

| 顺序 | 事项 | 成本 | 为什么排这里 |

| 6 | 标准 6/7/8 感知与延迟优化 | 3~5 天 | **大头**，且与 Reflector 完全不搭界，是独立的三块工作 |
