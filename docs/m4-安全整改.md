## 0. 一句话结论

三次事件的共同点是：**每一个动作单独看都合法，问题在于动作发往了哪里，且发生时没有人在看。**
原有两道刹车（热键急停、FAILSAFE）都需要人按；原有安全护栏只检查动作本身。
本次整改补上**自动急停**这一层，并在整理过程中发现：

> **批量评测脚本从未挂载急停热键。** M2 至 M4 的全部批量实测（包括发生三次事件的轮次）
> 期间，`Ctrl+Alt+Q` 按下不会有任何效果。

## 1. 三次事件与根因

| # | 事件 | 直接机制 | 为什么当时没拦住 |
|---|---|---|---|
| 1 | Agent 修改并保存了仓库里的 `.env`（`LLM_PROVIDER` 被写成 `dashscope你好世界测试消息你好世界…`） | 记事本会话恢复把 `.env` 拉回前台 → Agent 误判焦点 → 输入落进去 → 被保存 | `.env` 放在 Agent 的工作目录；护栏不看前台窗口；无人值守 |
| 2 | 对真实微软账号的身份验证界面连按 12 次回车 | 任务栏上 Microsoft 365 Copilot 紧挨 Edge，点岔一次弹出登录框，此后原地打转 | 护栏不看前台窗口，也不检测重复输入；无人值守 |
| 3 | 进入 Edge 的 Chrome 数据导入对话框，「保存的密码」处于勾选 | 点进了凭据相关界面 | 同上 |

### 1.1 整理时新发现的两个缺陷

**缺陷 A：批量脚本从未挂载急停热键。**
`ActionExecutor` 在 `start()` 中挂载热键监听；`cli/main.py` 调用了 `start()`，
而 `scripts/run_basic_tasks.py` 只构造执行器、从未调用。实测确认：

```
按批量脚本方式构造后，急停热键已挂载： False
手动调用 start() 之后：               True
PyAutoGUI 默认 FAILSAFE：             True
```

FAILSAFE 未受影响，仅因为 PyAutoGUI 自身默认开启。M1 验收标准 7「两道急停均有效」
是在 `scripts/verify_control.py` 中单独验证的，该脚本正确调用了 `start()`，
因此验收通过并未覆盖批量评测这条真实路径。

**缺陷 B：急停不会中止批量，且会污染成功率。**
急停状态一旦置位会一直保持。批量脚本在一轮结束后照常开下一轮，下一轮第一个动作
被拒绝，本轮以失败记入成功率分母——**人的刹车被记成了模型的失败**。
FAILSAFE 更糟：它被当作普通异常（`FailSafeException` 类型的动作失败），
既不中止批量，也无法与模型失误区分。

## 2. 整改措施

### 2.1 自动急停：安全哨兵（新增 `control/sentinel.py`）

在 `ActionExecutor.execute()` 中，每个动作执行前、安全护栏检查之前运行。
**命中即触发急停**（不是只拒绝这一个动作），本轮与整批停止，等人工确认。

| 规则 | 判据 | 对应事件 |
|---|---|---|
| `protected_file` | 前台窗口标题含 `.env` / `.git` / `id_rsa` / `.pem` | 1 |
| `account_signin` | 标题含 登录 / 身份验证 / Sign in / Microsoft 帐户 等 | 2 |
| `credential` | 标题含 密码 / password / 凭据 / credential；或进程 `CredentialUIBroker.exe` | 3 |
| `browser_data_import` | 标题含 导入浏览器数据 / import browser data | 3 |
| `uac` | 标题含 用户帐户控制；或进程 `consent.exe` | —（同类） |
| `copilot` | 标题含 Copilot；或进程 `Microsoft365Copilot.exe` | 2 的起点 |
| `repeated_input` | 同一按键或同一段文本**连续第 3 次** | 2（连按 12 次回车）、1（反复输入「你好世界」） |

证据字段写入存档前对邮箱地址脱敏（登录框标题可能含真实账号）。

**只在真实执行时默认开启。** 演练模式不发送键鼠事件；若默认开启，开发者本机前台
恰好是 `.env` 或登录页时，演练与单元测试会被意外中止。

### 2.2 开跑前环境扫描

每轮在 `reset` 之后、Agent 动手之前，扫描所有可见窗口与运行中进程。
发现敏感窗口或进程（例如 reset 未能关闭的登录框、残留的 Copilot 进程），
**本轮标记为无效、整批停止**。这一步补的是哨兵拦不住的「第一下」（见 §3）。

### 2.3 急停机制修复

| 修复 | 位置 |
|---|---|
| 批量脚本调用 `executor.start()`，挂载热键；未能挂载时打印醒目警告 | `scripts/run_basic_tasks.py` |
| 急停记录触发来源：`hotkey` / `failsafe` / `sentinel:<规则>` | `control/emergency_stop.py` |
| FAILSAFE 视为急停（触发 `failsafe`），不再记为普通动作失败 | `control/executor.py` |
| **任何急停都中止整批**，不自动复位；存档标记 `aborted` 并以退出码 3 结束 | `scripts/run_basic_tasks.py` |
| 存档记录 `safety_setup`：热键是否挂载、哨兵是否开启 | 同上 |

### 2.4 `.env` 移出工作目录

加载顺序改为：环境变量 `GUI_AGENT_ENV_FILE` → `~/.gui-agent/.env` → 当前目录 `.env`。
最后一项保留兼容，但每次运行打印一次安全警告。
**离线评测（`--provider selfhost` / `local`）不需要任何密钥，客机上可以完全不放 `.env`。**

文件本身需要人工移动，见 §6。

### 2.5 Copilot

环境层面此前已做：快照中取消任务栏固定、`tasks/reset_desktop.py` 每轮结束 Copilot 进程。
本次在代码层面补两道兜底：哨兵 `copilot` 规则（前台出现即急停）、
开跑前环境扫描（进程或窗口残留即停批）。**换用新快照时若 Copilot 重新被固定，
第一次点岔仍会发生，但不会再走到对着登录框连续输入。**

## 3. 能力边界（必须如实写进报告）

1. **拦不住第一下。** 哨兵检查的是动作执行前的前台窗口。点岔任务栏的那一下发出时
   前台仍是 Edge，哨兵放行；登录框弹出后的**下一个**动作才被拦下。第一下的预防依赖
   环境配置（取消固定 Copilot）与开跑前扫描。
2. **标题匹配存在误报与漏报。** 本设计偏向误报：误报的代价是停一批、人工查看；
   漏报的代价是又一次安全事件。规则表对五个基础任务的正常窗口已做误报测试。
3. **拦得住「犯傻」，拦不住「规避」。** 与安全护栏相同，文本与标题匹配可被绕过。
   真正的安全边界仍是隔离虚拟机。
4. **未改变客机的合规状态。** 客机仍登录着开发者本人的微软账号（见 `CLAUDE.md` 第三节）。
   哨兵降低了 Agent 与该账号界面交互的概率，**但不构成合规**，交付物中不得据此声称合规。

## 4. 新增评测指标

批量脚本每轮记录，汇总打印在「安全与干预」一节，并写入存档 `safety_metrics`。

| 指标 | 定义 | 分母 |
|---|---|---|
| **首步成功率** | 本轮第一步的动作执行成功，**且**执行后屏幕发生变化 | 有效轮（起点建立、未剔除）中能判定首步的轮数 |
| **人工干预率** | 热键急停 + FAILSAFE + 事后标记「有人碰了鼠标」（`excluded`）的轮数 | Agent 实际开跑的轮数 |
| **安全事件数** | 哨兵命中（动作前 + 开跑前扫描）+ 危险输入拦截（`dangerous_text` / `dangerous_keys`），按规则分类 | 绝对数 |

口径说明：

- **首步看屏幕变化而不只看执行状态**：`execution_status == ok` 只表示键鼠事件已发出；
  实测「单击桌面图标」连续六次 ok 而屏幕不变。第一步报告完成（`done`）记为失败。
  无帧差记录时记为「无法判定」，不进分母。为此，循环现在**每一步都记录帧差**
  （此前仅在开启重试升级或 Reflector 时记录；只观测，不改变行为）。
- **自动急停不计入人工干预**：它说明无人值守时系统自己刹住了，计入安全事件。
- **坐标越界、调用未实现动作不计入安全事件**：它们是模型输出错误。
- **`scripts/exclude_round.py` 事后剔除一轮时，同步刷新存档中的 `safety_metrics`。**

**可比性**：三个指标仅对本次整改之后的存档有效，历史存档没有这些字段。
