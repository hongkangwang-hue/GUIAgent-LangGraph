## 摘要

桌面 GUI 智能体需要在给定屏幕截图与当前子任务的条件下，输出一个可执行的结构化动作。
在消费级硬件上部署时，开放权重的小规模视觉语言模型（VLM）是现实选择，但其零样本表现
往往无法满足结构化输出的要求。本文以 Qwen2.5-VL-3B-Instruct 为基座，在 ScreenAgent
公开数据集的桌面轨迹上构建了覆盖八类动作的单步动作生成数据集（训练 1783 条、验证 375 条，
按会话隔离划分），采用 QLoRA 进行参数高效微调，仅训练 1.79% 的参数，峰值显存 7.4GB。

离线评测表明，微调使输出格式合规率由 24.0% 提升至 100.0%，动作类型准确率由 15.5% 提升至
59.7%，坐标误差中位数下降 66%。然而，同一模型在隔离虚拟机中执行五个基础桌面任务时，
在唯一一轮环境受控的端到端测试中成功率为 **0/25**。我们通过两项分析定位了这一迁移失效的成因：
其一，**训练与部署的图像分辨率不同构**——部署环境的截图被模型预处理压缩至 0.622 倍，
单变量配对实验显示此时动作类型判断不受影响（47/53 对 47/53），而坐标命中率（r=50）
由 53% 崩溃至 4%；其二，**微调引入了"过早报告完成"的退化**，`done` 误报率由 7.8% 升至
36.5%，占全部动作类型错误的 53.0%，端到端测试中 25 轮全部以模型自报完成告终。

本文的结论是：QLoRA 微调能够可靠地习得输出格式与动作语义，但坐标定位能力对输入分辨率
高度敏感，且训练数据中无参数动作的高占比会诱发系统性的提前终止。二者均有已知的低成本修复路径。

**关键词**：GUI 智能体；视觉语言模型；QLoRA；动作生成；分布偏移；训练—部署同构

## 1 引言

### 1.1 研究背景

GUI 智能体的目标是让模型"看懂屏幕、操作电脑"。以 UI-TARS[1]、Claude Computer Use[9]
为代表的系统已经展示了这一方向的可行性，但它们或依赖大规模专有训练，或依赖闭源云端模型。
对于需要本地部署、数据不出本机的场景，开放权重的小规模 VLM 是更现实的选择。

本项目此前的阶段（第 2–4 周）已构建了完整的模块化 GUI 智能体系统：规划器将用户指令拆解为
子任务，执行器在每一步观察截图并输出一个结构化动作，由控制层转换为真实键鼠事件，
任务成败由程序化判据（进程、窗口标题、文件内容）判定。本阶段关注的是**执行器模型**本身：
当执行器由一个 3B 参数的本地模型承担时，它的能力瓶颈在哪里，参数高效微调能改善多少。

### 1.2 研究问题

基座模型在本任务上的零样本表现很差（见 §5.1）：约四分之三的输出不符合输出规范
（无法解析为 JSON、动作不在允许集合内或坐标非整数），因而无法被执行。
这提示瓶颈可能首先在于输出规范而非视觉理解。基于此，本文围绕以下四个研究问题展开：

- **RQ1**　QLoRA 微调能否提升小规模 VLM 在 GUI 单步动作生成上的表现？提升来自哪些方面，是否伴随退化？
- **RQ2**　提示词工程能在多大程度上补充或替代微调？
- **RQ3**　离线验证集上的提升能否迁移到实际部署环境？哪些因素决定迁移？
- **RQ4**　微调后的模型在真实桌面任务上的端到端表现如何，失败的机制是什么？

### 1.3 本文贡献

1. 构建了一个覆盖八类动作、按会话隔离划分、带数据指纹的单步动作生成数据集，并记录了
   一次因准入条件与任务目标不一致而导致的数据集重建（§3.2）。
2. 给出微调前后在格式、动作类型、坐标、分动作类型四个层面的对比，并识别出一项由微调
   引入的退化（§5.1）。
3. 通过单变量配对实验，将"离线提升无法迁移"归因到输入缩放强度，并证明其只影响空间定位、
   不影响语义判断（§5.3）。
4. 在受控环境下给出端到端结果，并将失败机制与离线分析中识别的退化对应起来（§5.4）。

## 2 相关工作

### 2.1 GUI 智能体的两条技术路线

现有工作大致分为两条路线。**端到端原生路线**将感知、规划、定位与动作生成置于单一模型中，
UI-TARS[1] 以大规模 GUI 轨迹训练原生智能体模型，CogAgent[2] 则通过高分辨率视觉编码器
专门处理 GUI 截图。这条路线端到端可优化，但训练成本高，且错误难以分解归因。

**模块化流水线路线**将能力拆分为独立模块。ScreenAgent[3] 将一次交互划分为规划、执行、
反思三个阶段，每个阶段单独调用视觉语言模型。本项目采用模块化路线，本文研究的对象
正是其中的执行阶段；本文使用的训练数据也来自 ScreenAgent 公开的交互轨迹。

### 2.2 GUI 视觉定位

"给定自然语言描述，在截图上指出对应元素的位置"被称为 GUI grounding。SeeClick[4] 将其作为
独立能力训练与评测，并发布了 ScreenSpot 基准；OS-ATLAS[5] 通过大规模跨平台数据进一步提升了
定位精度。通用 VLM 也开始内置定位能力，Qwen2.5-VL[6] 可直接输出点坐标或边界框。

值得注意的是，这类模型的视觉编码器通常对输入像素总数设有上限，超出时对图像等比缩放。
已有工作多关注定位精度本身，而较少讨论**训练与部署时缩放强度不一致**带来的影响——
这正是本文 §5.3 的研究对象。

与直接回归坐标相对，Set-of-Mark[7] 类方法先在图像上为候选元素编号，再让模型选择编号，
将连续的坐标回归问题转化为离散选择问题。本文 §8 将其列为未来工作。

### 2.3 参数高效微调

在消费级硬件上适配大模型时，LoRA[10] 冻结主干权重、仅训练低秩旁路矩阵；QLoRA[11] 进一步
将主干量化为 4-bit NF4，使数十亿参数模型可以在单张消费级显卡上完成微调。本文采用 QLoRA。
需要指出的是，LoRA 产出的适配器权重无法上传至公共 API 平台，因此微调本身即决定了模型
必须本地部署。

### 2.4 评测方法

WebArena[8] 提出以程序化的功能正确性判定评估智能体，而非依赖模型自述或人工目测。
本项目的端到端评测沿用这一思路：任务成败由进程、窗口标题或文件内容判定，与模型是否
自报完成无关。本文 §5.4 的结果将说明这一设计在本研究中的必要性。

## 3 方法

### 3.1 任务形式化

本文研究**单步动作生成**：给定一张界面截图 $I$ 与当前子任务的自然语言描述 $s$，
模型输出一个结构化动作 $a$：

```
输入   I：1024×768 的界面截图
       s：当前子任务，例如「确认FastAPI包已安装」
输出   a：{"action": "key", "keys": "ctrl+shift+`"}
```

动作空间包含八类：`left_click`、`double_click`、`mouse_move`（带坐标）；`type`（带文本）、
`key`（带按键）、`scroll`（带方向）、`wait`（带时长）；以及 `done`（表示子任务完成，**无参数**）。
坐标统一归一化到 $[0, 1000)$，与图像像素尺寸无关，避免把分辨率信息混入标签。

选择子任务而非会话级总目标作为指令，是因为 ScreenAgent 一个会话的十余步共享同一句总目标；
以总目标为指令时，同一句话会对应多个不同的正确动作，构成矛盾监督。

### 3.2 数据集构建

**来源。** ScreenAgent 数据集（Apache-2.0）的桌面端交互轨迹。

**划分策略。** 一个会话是一串连续操作，相邻步骤的截图高度相似。若按样本随机划分，
同一会话的相邻步骤会分别落入训练集与验证集，造成难以察觉的泄漏。因此本文**以会话为单位**
进行划分，并将划分结果冻结为文件（种子 `20260913`，指纹 `c1fd6437d3df7178`），
训练前校验指纹。代价是验证集规模无法精确控制。

**表 1　数据集规模与划分**

| | 训练集 | 验证集 |
|---|---:|---:|
| 样本数 | 1783 | 375 |
| 会话数 | 165 | 38 |
| 两集合会话交集 | 0 | |

按划分文件，训练集与验证集的候选样本分别为 2518 与 524 条。实际生成时剔除了 884 条，
其中绝大部分为规划器的训练目标（"总目标 → 子任务列表"，不属于执行器动作），其余为缺少
终点的拖拽与不完整的按下/抬起事件。对后者，本文选择剔除而非补全：以只有起点的拖拽作为
监督信号，模型学到的将是"拖拽等价于单击"。

**表 2　动作类型分布（训练集与验证集合计 2158 条）**

| 动作 | 条数 | 占比 |
|---|---:|---:|
| `done` | 897 | **41.6%** |
| `left_click` | 520 | 24.1% |
| `key` | 254 | 11.8% |
| `type` | 216 | 10.0% |
| `double_click` | 91 | 4.2% |
| `mouse_move` | 74 | 3.4% |
| `wait` | 65 | 3.0% |
| `scroll` | 41 | 1.9% |

分布高度不均衡：`done` 单类占 41.6%，而 `scroll` 不足 2%。§6.2 将讨论这一分布与微调后
退化之间的关系。数据集中全部 2158 张截图均为 1024×768，这一事实在 §5.3 中至关重要。

**数据集的重建。** 本文使用的是重建后的第二版数据集。第一版的样本池仅 716 条，且**全部为
带坐标的鼠标动作**，`type`、`key`、`done` 一条都没有。原因是其准入条件要求"样本必须带坐标"——
该条件写于项目目标还是"坐标定位"的阶段，目标调整为"动作生成"后未随之修改。由于第 4 周的
五个基础任务中有四个需要键盘输入，第一版数据集从结构上无法支撑这些任务。

重建同时改变了四个因素：样本规模、动作种类、指令粒度（总目标 → 子任务）、指令语言
（英文 → 中文），并将按键名从 X11 词表映射到执行器使用的 pyautogui 词表。因此本文**不将
新旧版本的差异归因于其中任一因素**。此外，两版划分的会话存在交叉——新验证集的 38 个会话中
有 20 个出现在旧版训练集中——故两版的评测数字不可直接比较，旧版结果仅在附录 A 中单独报告。

### 3.3 模型与 QLoRA 微调

**表 3　训练配置与开销**

| 项 | 取值 |
|---|---|
| 基座 | Qwen2.5-VL-3B-Instruct，4-bit NF4 量化加载（双重量化），bf16 计算 |
| LoRA | $r=16$，$\alpha=32$，dropout 0.05 |
| 目标模块 | 注意力 `q/k/v/o_proj`，前馈 `gate/up/down_proj` |
| 优化器 | AdamW（8-bit），学习率 $1\times10^{-4}$，2 epoch |
| 批大小 | 1，梯度累积 8，共 446 步 |
| 显存优化 | gradient checkpointing |
| 图像上限 | `max_pixels` $= 896^2 = 802{,}816$ |
| 可训练参数 | 37,152,768 / 2,071,177,216 = **1.79%** |
| 训练时长 / 峰值显存 | 93 分钟（RTX 4090 24GB）/ **7,458 MB** |

峰值显存 7.4GB 表明该配置可在 8GB 消费级显卡上完成训练。

**训练正确性的验证。** 本文报告的模型是第二次训练的结果。第一次训练存在两个缺陷：
（1）训练提示词仅列出 4 个鼠标动作，而训练目标中 62.1% 为 `type`、`key` 或 `done`；
（2）标签掩码偏移了 3 个 token，模型实际学习的目标是 `": true}<|im_end|>` 而非
`{"done": true}`。修复后保持数据与超参不变重新训练。

一个值得记录的观察是：**两次训练的 loss 曲线几乎无法区分**（第一次第 10 步 0.6080、末点 0.1996；
第二次分别为 0.5607、0.2111）。这意味着 loss 不能作为修复生效的证据。本文采用三项结构性证据：
（1）单元测试直接断言掩码位置；（2）训练日志中"找不到 assistant 起始标记"的告警数为 0；
（3）训练后 348 个 `lora_B` 矩阵全部非零——由于 `lora_B` 以零初始化，若标签被完全掩码，
它将保持为零，而 loss 仍可正常下降。

> **数据来源说明。** 训练服务器在下载权重后失联，原始训练日志未能取回。表 3 中的训练开销、
> 两次训练的 loss 值及上述第（2）（3）项证据，均来自当时从服务器读出后存档的
> `模型权重/20260827-174327/训练记录.md`，是本文唯一不能从原始日志重算的数值。
> 第（1）项可在交付包内直接运行复现；权重文件已逐文件 MD5 校验。

### 3.4 评测协议

**离线评测。** 在 375 条验证集上逐条推理，记录以下指标：

| 指标 | 定义 | 分母 |
|---|---|---:|
| 格式合规率 | 输出可解析为 JSON、动作属于允许集合、坐标为整数 | 375 |
| 动作类型准确率 | 预测动作类型与真值一致 | 375 |
| 坐标误差 | 预测点与真值点的欧氏距离（$[0,1000)$ 空间） | 给出坐标的样本 |
| 联合命中 @r | 动作类型正确**且**坐标误差 $\le r$ | 99（坐标类样本） |
| 全量命中率 | 动作类型正确，且坐标类误差 ≤50、其余类关键参数（文本、按键、方向）一致 | 375 |
| `done` 误报率 | 真值非 `done` 而预测为 `done` 的比例 | 219（非 `done` 样本） |

本文将**格式合规**与**动作类型准确**分开记录，以区分"学会了输出规范"与"学会了做什么"。
同时单独度量 `done` 误报率：由于 `done` 在验证集中同样占 41.6%，若模型倾向于多报完成，
总体命中率会随之上升，从而掩盖一种实际有害的行为。

**端到端评测。** 在隔离的 Windows 11 虚拟机中执行五个基础任务（打开浏览器、搜索指定内容、
打开指定文件、发送消息、关闭应用），每个任务 5 轮。成败由程序化判据决定，与模型是否自报完成无关。
每轮记录虚拟机快照名，以保证环境可追溯。

## 5 实验结果

### 5.1 RQ1：微调对动作生成的影响

**表 5　微调前后主结果（验证集 375 条）**

| 指标 | 微调前 | 微调后 | 变化 |
|---|---:|---:|---:|
| 格式合规率 | 24.0% | **100.0%** | +76.0pp |
| 动作类型准确率 | 15.5% | **59.7%** | +44.3pp |
| 坐标误差中位数 | 144.5 | **49.7** | −66% |
| 联合命中 @25 | 0.0% | 13.1% | +13.1pp |
| 联合命中 @50 | 1.0% | 24.2% | +23.2pp |
| 联合命中 @100 | 2.0% | 37.4% | +35.4pp |
| 全量命中率 | 4.0% | **49.1%** | +45.1pp |
| `done` 误报率 ↓ | 7.8% | 36.5% | **+28.8pp（退化）** |
| 推理延迟中位数 | 997 ms | 804 ms | −193 ms |

**表 6　按真值动作类型分解**

| 真值动作 | 样本 | 类型准确率（前 → 后） | 命中率（前 → 后） |
|---|---:|---|---|
| `done` | 156 | 5.1% → 84.6% | 5.1% → 84.6% |
| `left_click` | 76 | 26.3% → 51.3% | 1.3% → 21.1% |
| `key` | 58 | 24.1% → **22.4%** | 0.0% → 13.8% |
| `type` | 46 | 30.4% → 63.0% | 8.7% → 39.1% |
| `mouse_move` | 12 | 0.0% → **0.0%** | 0.0% → 0.0% |
| `double_click` | 11 | 0.0% → 81.8% | 0.0% → 72.7% |
| `wait` | 10 | 20.0% → **0.0%** | 20.0% → 0.0% |
| `scroll` | 6 | 0.0% → 33.3% | 0.0% → 33.3% |

**发现 1：输出规范是微调最确定的收益。** 基座模型的格式合规率仅 24.0%，意味着约四分之三的
输出不符合规范而无法被执行；微调后 375 条全部合规。这一结果支持 §1.2 的推测——基座的首要瓶颈在于输出
规范而非视觉理解。

**发现 2：坐标定位有实质改善，但绝对水平仍然有限。** 坐标误差中位数下降 66%，联合命中 @50
由 1.0% 升至 24.2%。然而这意味着在"应当点击"的样本中，仍有约四分之三未能在 50 单位半径内
命中目标（该半径约为屏幕宽度的 5%）。

**发现 3：微调引入了一项显著退化。** `done` 误报率由 7.8% 升至 36.5%。在全部 151 条动作类型
错误中，"真值应继续、模型却报告完成"占 80 条，即 **53.0%**。若仅消除这一类错误，动作类型准确率
的上界为 59.7% → **81.1%**。由于验证集中 `done` 本身占 41.6% 且其命中率达 84.6%，
总体命中率 49.1% 在相当程度上由 `done` 支撑，**仅报告总体指标会高估微调效果**。
该退化的成因在 §6.2 中讨论。

**发现 4：部分动作类型未学会或出现退化。** `mouse_move` 前后均为 0%；`wait` 由 20.0% 降至 0.0%；
`key` 在 58 条样本上由 24.1% 微降至 22.4%。前两类样本量较小（12、10 条），结论强度有限；
但 `key` 的样本量说明"样本不足"不能完全解释这一现象。

> **在进入端到端评测之前**，基于发现 3，我们预期端到端成功率将显著低于离线的 49.1%，
> 因为"该继续时报告完成"在真实任务中意味着该轮直接失败。这一预期先于 §5.4 的实验写下。

### 5.2 RQ2：提示词工程的作用

实际部署时，执行器使用的是系统提示词模板 `executor_v0`，而非训练时的提示词。
为评估提示词对微调模型的影响，本文在 99 条坐标类样本上**仅替换提示词**进行对照。

**表 7　提示词对照（微调模型，坐标类样本 99 条）**

| 提示词 | 格式合规 | 动作类型准确 | 误报 `done` | 给出坐标 | 误差中位数 | 坐标 ≤50 |
|---|---:|---:|---:|---:|---:|---:|
| 训练提示词 | 100% | 48% | 31% | 54 | 49 | 52% |
| `executor_v0` | 98% | **58%** | **24%** | **63** | **45** | **56%** |

`executor_v0` 使动作类型准确率提高 10 个百分点、`done` 误报减少 7 个百分点，给出坐标的样本
增加 9 条，坐标误差与命中率亦略有改善；代价是格式合规率下降 2 个百分点。
（由于这 99 条样本的真值均为点击类，表中的"误报 `done`"即全部 `done` 输出。）

项目中还存在带 few-shot 示例的 `executor_v1` 与增加思维链的 `executor_v2`。在端到端测试中
观察到，微调后的模型会**逐字复制 few-shot 示例中的坐标**——其输出格式合规、动作类型也可能正确，
仅坐标为示例中的常数，这类错误无法被格式合规率或动作类型准确率捕捉。评测代码为此专门增加了
逐字复制检测。对已将输出规范内化到权重中的微调模型而言，few-shot 示例的收益有限而风险明确，
因此部署时选用零样本的 `executor_v0`。

对**基座模型**，项目早期在旧版验证集上进行过三档提示词消融（附录 A.2）：few-shot 使格式合规率
由 0/142 显著提升至 7/142（Fisher 精确检验 $p=0.0145$），思维链的进一步提升不显著（$p=0.798$），
最佳配置为 6.3%，而同期微调达到 100%。

**RQ2 的回答**：提示词工程对基座模型有统计显著但量级有限的作用，与微调相差约一个数量级；
对微调后的模型，合适的零样本提示词能带来约 10 个百分点的额外提升，而 few-shot 示例会引入
坐标复制的风险。

### 5.3 RQ3：离线收益为何无法迁移——输入缩放强度

**问题的提出。** Qwen2.5-VL 对输入图像的像素总数设有上限 `max_pixels` $=802{,}816$，
超出时等比缩放。表 8 对比了训练与部署两种情形：

**表 8　训练与部署的输入分辨率**

| 情形 | 分辨率 | 像素数 | 缩放系数 |
|---|---|---:|---:|
| 训练集（全部样本） | 1024×768 | 786,432 | **1.000** |
| 部署客机 | 1920×1080 | 2,073,600 | **0.622** |

训练图像恰好低于上限、不发生缩放；而部署时的截图被压缩至 0.622 倍。**训练与部署在输入尺度上
不同构**。需要说明的是，项目在第 1 周的计划中已明确"固定以 1024×768 为主模型坐标系"，
但客机长期运行在 1920×1080 下，这一不一致直到本阶段才被识别。

**实验设计（E3）。** 为隔离缩放强度这一变量，本文将验证集图像**保持 4:3 宽高比与内容不变，
等比放大至 1664×1248**，使其缩放系数（0.6218）与部署环境一致。由于等比放大不改变归一化坐标，
真值无需变换。对比时采用严格配对：同一样本、真值为坐标类、两种条件下均给出坐标，共 53 条。

**表 9　缩放强度的配对实验（n = 53）**

| 条件 | 误差 P25 | 误差中位数 | 误差 P75 | ≤25 | ≤50 | ≤100 | 动作类型正确 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 原图（缩放 1.000） | 25 | **49** | 88 | 26% | **53%** | 77% | 47/53 |
| 放大（缩放 0.622） | 167 | **255** | 379 | 0% | **4%** | 4% | 47/53 |

逐样本比较，放大后误差增大的样本为 47/53（89%），无一相同。

**分析。** 结果呈现出清晰的分离：**动作类型判断完全不受影响**（两种条件下均为 47/53），
**空间定位则几乎完全失效**（≤50 的命中率由 53% 降至 4%，误差中位数扩大约 5 倍）。
这表明模型在缩放后的图像上仍能识别"应当做什么"，但无法准确给出"在哪里做"。
一个合理的解释是：语义判断依赖界面的整体布局与显著元素，对分辨率下降具有鲁棒性；
而坐标输出依赖细粒度的空间对应关系，模型仅在训练时见过的尺度上习得了这种对应。

**RQ3 的回答**：离线收益无法迁移的首要原因是训练与部署的输入缩放强度不一致。该因素选择性地
破坏空间定位能力，而不影响语义层面的动作判断。对应的修复成本为零——将部署环境的屏幕分辨率
固定为 1024×768 即可恢复同构。

### 5.4 RQ4：端到端表现与失败机制

**实验（E4）。** 将客机分辨率固定为 1024×768（快照 `eval-baseline-llm-1024x768`），
消除 §5.3 识别的不同构，运行五个基础任务各 5 轮。

**表 10　端到端结果（程序化判定）**

| 任务 | 成功 |
|---|---:|
| 打开浏览器 | 0/5 |
| 搜索指定内容 | 0/5 |
| 打开指定文件 | 0/5 |
| 发送消息 | 0/5 |
| 关闭应用 | 0/5 |
| **合计** | **0/25** |

这是一次有效运行而非系统故障：共执行 154 步，规划器正常拆解出 86 个子任务，程序化判据逐轮执行
（例如"打开指定文件"的第 1 轮已成功启动记事本，但窗口标题判据未通过）。

**失败机制。** 结果与 §5.1 发现 3 所预期的机制一致：

- **25 轮全部以模型自报完成告终**，而程序化判定为 0/25；
- 在 86 个子任务中，有 **19 个（22.1%）在未成功执行任何动作的情况下即被报告完成**。

即模型在尚未采取有效行动时便宣告子任务完成，导致规划器进入下一个子任务，任务整体失败。
这也说明了 §2.4 所述程序化判定的必要性：若以模型自报为准，本轮成功率将被记为 25/25。

**与早期结果的关系。** 在分辨率不同构的 1920×1080 环境下，同一模型与提示词曾测得 5/25。
本文不将其作为有效结果，原因有二：（1）该配置下坐标精度已被证明严重受损（§5.3）；
（2）5 次成功全部来自"打开浏览器"一项任务，轨迹分析显示模型点击的很可能是桌面上的
Windows 聚焦图标而非浏览器图标——前者同样会启动 `msedge.exe`，从而满足了判据"浏览器进程在运行"。
消除分辨率不同构后该任务为 0/5，说明此前的成功并非来自正确定位。两轮之间除分辨率外快照也不同，
严格而言不构成单变量对照。

**RQ4 的回答**：在受控环境中，微调模型的端到端成功率为 0/25。在分辨率同构的前提下，主要失败机制
是微调引入的提前报告完成，该机制在离线分析中已被识别并预测。

## 6 讨论

### 6.1 格式、语义与定位是三种可分离的能力

本文的结果表明，"微调是否有效"不宜以单一指标回答。至少可以区分三种能力：

| 能力 | 衡量指标 | 微调效果 | 对缩放的敏感度 |
|---|---|---|---|
| 输出规范 | 格式合规率 | 24.0% → 100.0%，彻底习得 | —— |
| 语义判断 | 动作类型准确率 | 15.5% → 59.7%，显著改善 | **不敏感**（47/53 → 47/53） |
| 空间定位 | 坐标命中率 | 1.0% → 24.2%，有限改善 | **极敏感**（53% → 4%） |

这一分解对系统设计有直接意义：既然模型在语义判断上相对可靠、在空间定位上脆弱，那么将定位
从模型输出中剥离——例如由界面结构信息（UIA、OCR）提供候选元素，模型只需选择编号——
可能比继续提升坐标回归精度更具性价比。

### 6.2 `done` 退化的成因：无参数动作的"低风险"特性

`done` 误报的上升可以从训练信号的结构上理解。在八类动作中，`done` 是**唯一不需要任何参数**的输出：
其他动作需要正确给出坐标、文本或按键才算命中，而 `done` 只要类型正确即被判为完全正确。
与此同时，`done` 占训练样本的 41.6%。两者叠加，使"输出 `done`"成为在训练分布下期望损失最低
的保守策略之一。

值得注意的是，这一退化**无法通过加强训练本身消除**。ScreenAgent 的标注描述的是"这一步应该做什么"，
不包含"上一步是否已经生效"的信息；模型缺乏可学习的信号来区分"已经点击"与"已经点中"。
因此，除了在训练端对 `done` 降采样外，系统层面还需要独立于模型的完成校验。

### 6.3 训练—部署同构是被低估的前提

§5.3 的发现本质上是一种分布偏移，但它并非来自数据内容，而是来自**预处理参数与部署环境的交互**：
训练数据恰好低于 `max_pixels` 上限，部署截图恰好高于上限。这类偏移不会产生任何报错，
离线评测也无法察觉，因为验证集与训练集共享同一分辨率。本项目中，训练分辨率这一事实早已记录在
数据集元信息中，却未被用于与部署配置进行比对。这提示：对于依赖视觉定位的模型，
训练与推理的输入尺度应作为部署前的显式检查项，而非默认假设。

### 6.4 方法论层面的观察

**loss 不足以验证训练正确性**（§3.3）。两次训练——一次存在标签掩码缺陷、一次已修复——
的 loss 曲线几乎无法区分，结构性检验（掩码断言、适配器非零检查）是必要的补充。

**聚合指标会掩盖有害行为**（§5.1）。当某一动作类型在验证集中占比较高时，模型对该类型的偏好
会同时抬高总体准确率并损害实际任务表现。分动作类型报告、并单独度量误报率，是识别此类问题的前提。

**模型自报不可作为成功判据**（§5.4）。本轮若采信模型自报，成功率将为 100%，而实际为 0%。

## 7 有效性威胁

**离线评测与部署的量化配置不一致。** E1–E3 均以 bf16 加载模型，而部署到客机的本地服务默认采用
4-bit NF4。旧版验证集上的实验显示量化使微调模型的动作类型准确率下降 9.2 个百分点（附录 A.1）；
新版验证集上的 4-bit 结果尚未测量。因此表 5 的数值应视为部署配置下的上界。

**验证集与训练集同分布。** 验证集虽按会话隔离，但与训练集来自同一数据源与同一类应用，
其结果反映的是分布内泛化。目前**没有任何带人工标注的客机截图评测**，训练集中也不包含客机截图；
例如"开始按钮"在训练数据中位于 Win10 的左下角，而客机为 Win11 的底部居中布局。

**超参数未经搜索。** 本文仅在 $r=16,\ \alpha=32$、学习率 $10^{-4}$、2 epoch 这一组配置上进行实验。
关于"LoRA 对输出规范有效、对坐标有限"的结论，严格而言仅在该配置点成立。

**数据集重建非单变量改动。** §3.2 所述重建同时改变了四个因素，无法将效果归因于其中任一项。

**端到端证据有限。** 受控环境下仅有一轮微调模型的端到端数据（25 次运行），且缺少同一配置下的
基座模型对照；§5.4 与早期 1920×1080 结果之间同时改变了分辨率与快照。

**部分数值来自存档而非原始日志。** 训练开销与 loss 值来自训练记录存档（§3.3）。

## 8 结论与未来工作

本文在消费级硬件约束下，对 Qwen2.5-VL-3B 进行了面向 GUI 单步动作生成的 QLoRA 微调，
并从离线与端到端两个层面评估了其效果。主要结论如下：

1. **QLoRA 能以极低成本习得输出规范与动作语义**：仅训练 1.79% 的参数、7.4GB 显存，格式合规率
   达到 100%，动作类型准确率提升 44.3 个百分点。
2. **坐标定位能力对输入缩放强度高度敏感**：在与部署一致的 0.622 缩放下，坐标命中率由 53% 降至 4%，
   而动作类型判断不受影响。训练与部署的输入尺度同构是此类模型可用的前提。
3. **训练分布中无参数动作的高占比会诱发提前终止**：`done` 误报率上升至 36.5%，并在端到端测试中
   表现为全部 25 轮提前宣告完成。
4. 在受控环境中，当前模型的端到端成功率为 0/25；离线提升尚未转化为实际任务能力。

**未来工作**按预期收益与成本排序：

| 方向 | 针对的问题 | 预计成本 |
|---|---|---|
| 部署环境固定 1024×768，并在同一快照下重跑在线模型基线 | §5.3 的不同构；获得可比的对照组 | 零（快照已建立，离线模型已运行一轮） |
| 训练时对 `done` 降采样后重训 | §5.1 发现 3、§6.2 | 约 1.5 小时 GPU |
| 在新版验证集上补测 4-bit 离线结果 | §7 量化配置不一致 | 数小时 |
| 采集并人工标注客机截图，建立分布外评测集 | §7 同分布偏倚 | 1–2 天 |
| 以界面结构信息提供候选元素、模型选择编号（Set-of-Mark[7] 思路） | §6.1 空间定位脆弱 | 数天 |

## 附录 A　旧版验证集上的补充结论

> 以下结果基于重建前的旧版验证集（142 条，仅含点击类动作，英文总目标指令）。
> 由于口径不同且两版划分的会话存在交叉，**不可与正文数值并列比较**。
> 原始文件位于 `docs/m3-action/旧口径/`。

### A.1 量化对基座与微调模型的影响

**表 A1　动作类型准确率在 bf16 与 4-bit NF4 下的对比**

| 模型 | bf16 | 4-bit NF4 | 变化 |
|---|---:|---:|---:|
| 基座 3B | 41.5% | 7.0% | −34.5pp |
| 微调 3B | 85.2% | 76.1% | −9.2pp |

量化对基座的损害约为对微调模型的 3.8 倍。一个可能的解释是：微调将窄而确定的输出行为固化在权重中，
使其对量化噪声更具鲁棒性；该解释尚未经实验验证。其实际意义在于，在 8GB 显卡可容纳的 4-bit 配置下，
微调带来的动作类型提升为 +69.0pp，大于 bf16 下的 +43.7pp；代价是推理延迟增加 1.76 倍
（1656 → 2923 ms）。

### A.2 基座模型的提示词消融

**表 A2　三档提示词（基座 3B）**

| 指标 | 零样本 `executor_v0` | + few-shot `executor_v1` | + 思维链 `executor_v2` |
|---|---:|---:|---:|
| 格式合规率 | 0.0%（0/142） | 4.9%（7/142） | 6.3%（9/142） |
| 动作类型准确率 | 3.5% | 7.7% | 9.9% |

few-shot 的提升显著（Fisher 精确检验 $p=0.0145$），思维链的进一步提升不显著（$p=0.798$）。

### A.3 与在线 8B 模型的单步能力对比

**表 A3　联合命中 @50（分母均为 142）**

| 模型 | 联合命中 @50 |
|---|---:|
| 基座 3B（本地 4-bit） | 1.4% |
| 微调 3B（本地 4-bit） | 27.5% |
| `qwen3-vl-8b-instruct`（在线 API） | 30.3% |

在单步定位上，参数量更大的在线模型仅领先微调 3B 模型 2.8 个百分点。该结果需结合两点限制解读：
（1）验证集对微调 3B 为同分布留出集，对 8B 为未见数据，比较偏向 3B；
（2）8B 的原始结果文件产生于一个评测缺陷修复之前，其中 22 条"输出无法解析"被误记为"调用失败"
并排除出分母。直接汇总得到 35.8%（分母 120），将其按格式失败计入分母后为可比的 30.3%（分母 142）。
复算脚本显式执行此修正，并同时输出修正前后的数值。
